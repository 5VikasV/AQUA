# AQUA Development Rules

Always preserve the existing architecture.

Do not replace working code unless explicitly requested.

Prefer modifying existing files over creating unnecessary files.

Backend and frontend must remain separate.

Use the existing services whenever possible.

Reuse the shared API client.

Keep React components small.

Keep FastAPI routes thin.

Business logic belongs inside services.

Never invent a different architecture.

Never rename folders without being asked.

Give complete implementations.

Do not leave TODO placeholders.

Do not remove comments unless requested.

Before large refactors, explain the proposed changes.

Preserve Git history whenever possible.
